# Local API Validation Implementation Plan

**Goal:** Exercise the local project on the available desktop and add a bounded,
browser-free TAO.com source observation path without changing existing ledgers.

**Architecture:** A fixed-origin HTTP client captures validated JSON receipts.
A local job writes immutable per-run evidence and atomically publishes a separate
JSON/HTML summary. Existing collection, monitoring and recovered data stay intact.

**Tech Stack:** Python standard library, existing local-state utilities, pytest,
Windows CMD/PowerShell wrappers.

**Spec:** `docs/superpowers/specs/2026-11-09-local-api-design.md`.

## Global constraints
- No new GitHub Actions, automatic scheduler install, merge or visibility change.
- No implicit watchlist export, credentials or private data committed.
- Cap pages and response sizes; preserve provider timestamps and raw units.
- API evidence is not a reconciled wallet ledger or proof of complete coverage.

## Review focus
- HTTP 404/429/timeouts must be errors rather than zero activity.
- Unexpected schema, repeated cursors and oversized bodies must stop safely.
- Redirects and pagination must not leak requests to another origin.
- A failed run must preserve prior current reports and every recovered database.
- Windows tests must distinguish native runtime results from static checks.

## Tasks
1. Write failing tests for the fixed-origin JSON client and bounded collection,
   including the failure cases above. Implement `seo/sources/tao_api.py`.
2. Write failing tests for `seo/local_api.py` and `api-collect` dispatch. Implement
   local evidence receipts, checksums, clear coverage and atomic summary output.
3. Independently validate Windows scripts and add an offline smoke command.
4. Run live bounded API collection on Debian with public sample data, render the
   report, test backup/restore in disposable roots, and run full tests and lint.
5. Review changes, document exact successful checks and remaining Windows/ledger
   limitations, then publish only code/docs to the existing draft PR and verify
   its exact head. Never merge.
